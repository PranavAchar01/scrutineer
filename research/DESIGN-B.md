# DESIGN-B — "The Living Notebook": documentation as the engine of the SCRUTINEER loop

Angle: every round of the loop *is* a document. The Historian writes an executable race-weekend debrief (a marimo notebook) and compiles the team wiki; roles' skill files are recompiled from the wiki and never from raw failures; ARIA reads the season's runs and proposes the next hypothesis; the upgrade scene on the broadcast is literally the notebook cell that changed the role. Memory, provenance and auditability come first; lap time is what they buy.

Sources are the nine research threads in this directory (R1–R9, all fetched 2026-09-03/04). Every factual claim below carries the URL from those threads. Items the threads marked UNVERIFIED stay marked here.

---

## 1. Thesis and the loop

**Thesis.** The strongest 2026 evidence on self-improving loops says the same thing from four directions: the improver must read *distilled* evidence rather than raw failures (WikiSkill's proposer-has-wiki 63.7% vs. inference-has-wiki 60.9%, https://arxiv.org/html/2608.27454; Contextual Drag's 10–20% drop from failed attempts in context, https://arxiv.org/html/2602.04288v1); the evaluator and the record must sit outside the improver's write set (DGM deleted its own hallucination markers, https://sakana.ai/dgm/; tampering in 63–85% of DGM/HyperAgents/ADAS iterations with findings persisting along the winning lineage, https://arxiv.org/html/2609.00069); credit is reliable statistically across many runs, not per instance (Who&When, https://arxiv.org/abs/2505.00212); and the cost of cheap report generation shifts to tracing "which sentence rests on which evidence" (RSI survey §6.3, https://arxiv.org/html/2607.07663). So in this design the document is not a side effect of the loop — it is the only channel through which the loop is allowed to improve itself. A round's debrief notebook pulls FIA telemetry (Weave) into typed variables, computes credit, renders the stewards' verdict, and exposes one variable, `next_round_config`, that the next round consumes via `app.run()`. The Race Engineer proposes an upgrade as a *cell* in that notebook, so the diff that changed a role, the evidence it cites, and the gate it passed are one reproducible artifact — and marimo's DAG (`ctx.graph.ancestors("next_round_config")`) is the audit trail (https://docs.marimo.io/guides/reactivity/). The wiki is never rolled back; skills are. That asymmetry is the memory of the team.

## 2. THE CAST

The task family the CAR races on: small, hidden-test coding tasks (a pool of ~120 HumanEval/MBPP-style problems, split 40 QUALI-visible / 40 SEALED / 40 reserve for "regulation changes"), because tests give execution feedback — rung two of the verification hierarchy, above learned judges (https://arxiv.org/html/2607.07663 §5.2). Lap time = SICA's utility `U = 0.5·pass + 0.25·(1 − cost/cap) + 0.25·(1 − time/limit)` (https://arxiv.org/html/2504.15228), so cost is inside the score.

Rules from the evidence: one role upgraded per round (Optimas, GEPA, LLMSelector all update one component at a time, https://arxiv.org/abs/2507.03041, https://arxiv.org/abs/2507.19457, https://arxiv.org/abs/2502.14815); the team stays small and role-typed because self-organising teams lose up to 41.1% vs. their best member (https://arxiv.org/abs/2602.01011); every role's call logs full `inputs` because dropping inputs costs 76% of step-level attribution accuracy (https://arxiv.org/html/2604.22708v1). Every role's upgradeable artifact is an Agent Skills directory `skills/<role>/` — `SKILL.md` (frontmatter `name`, `description`, `metadata.version`), `scripts/`, `references/`, `tests/`, `.memory.md` — validated with `skills-ref validate` (https://agentskills.io/specification; `.memory.md` + `tests/`-before-registration from MUSE-Autoskill, https://arxiv.org/html/2605.27366v1). `metadata.version` is the part number shown in the garage.

## 4. CREDIT ASSIGNMENT

Three mechanisms, layered by trust, all landing in the notebook's `credit` cell. Step-level blame is never shown on screen (≤33% accuracy in every 2026 benchmark, https://arxiv.org/html/2604.22708v1); role-level blame is shown only after it accumulates.

**Tier 1 — PARC FERMÉ REPLAY (role-masking counterfactual; SHARP/C3 pattern).** For each failing lap and each in-lap role r: fetch the trace (`client.get_calls(filter=CallsFilter(trace_ids=[t]), include_feedback=True)`), find r's call by `attributes.role`, re-run only the *downstream* pipeline from that call's recorded `inputs` with r's output replaced by the GHOST CAR's version of r (`weave.ref(f"skill-{r}:{parent_version}").get()`), temperature 0, 2 seeds. `credit_r = U(actual) − U(with r replaced)`, with a bootstrap CI. Exact leave-one-out is "simpler, cheaper, and more effective than all approximate alternatives" for text agents (https://arxiv.org/abs/2603.06859); SHARP's `credit = R(τ) − R(τ \ m)` (https://arxiv.org/html/2602.08335v2); CIs per Causal Agent Replay (https://arxiv.org/abs/2606.08275). Written back as `call.feedback.add("scrutineer.credit", {"role": r, "delta_u": ..., "ci": [...]})`.

**Tier 2 — STEWARDS' INQUIRY (trace-judge + patch-replay).** A `weave.Scorer` (`BlameScorer`, all-at-once prompt from Who&When, https://github.com/mingyin1/Agents_Failure_Attribution) reads the full call tree — inputs and outputs — and emits `{role, mast_mode, explanation}` using the 14 MAST modes (https://arxiv.org/html/2503.13657). The verdict stands only if REFLECT's rule holds: patch that role's step, replay once, lap flips (https://arxiv.org/abs/2606.09071). Expect ~55–70% agent-level accuracy from a frontier judge (https://arxiv.org/abs/2509.03312); the replay check absorbs errors. Judge model ≠ any role's model.

**Tier 3 — CONSTRUCTORS' STANDINGS (statistical ledger).** The System1 CREDIT ROUTER converts each failing lap's Tier-1/Tier-2 evidence into a typed row `{blamed_role, blame_share: dict[role→float], confidence, needs_ablation}`; `needs_ablation=True` (low confidence) forces a Tier-1 replay before the row counts. Rows accumulate across laps and rounds in `wiki/standings.tsv` and in Weave feedback. Upgrade pick rule:

```
eligible = roles with ≥1 wiki pattern page status=open citing ≥3 laps   (evidence gate; Who&When "statistical-level")
score(r) = Σ blame_share[r] over failing laps × sqrt(occurrences)         (MemSkill d=(1−r)·c, https://arxiv.org/html/2602.02474v1)
tie-break = highest lap-time variance across trials                       (JoyAgents-R1 marginal-benefit rule)
exclude   = role upgraded last round                                      (block-coordinate alternation, https://arxiv.org/abs/2605.30227)
upgrade_pick = argmax score(r)  →  Team Principal may override in the notebook's mo.ui.dropdown
```

If no harness role's mask flips any lap in a cluster, the router emits `agent_error` (Co-Harness's model-side abstention, https://arxiv.org/html/2607.22688v1) and the pick is POWER UNIT — the only route to a weight update.

**The evidence chain, hop by hop (each hop is a resolvable ref, both directions):**

1. Weave call `c` (`trace_id`, `id`, `attributes.role`, `inputs`, `output`, `exception`) — https://docs.wandb.ai/weave/guides/tracking/call-schema-reference
2. Sandbox tool span on `c`'s lap: hidden-test `returncode` (the failure fact) — https://docs.wandb.ai/sandboxes/run-commands
3. Feedback on `c`: `scrutineer.credit` (Tier 1), `BlameScorer` result (Tier 2), `router` row (Tier 3) — https://docs.wandb.ai/weave/guides/evaluation/scorers
4. Wiki pattern page `wiki/patterns/pattern-0042.md` with `evidence: [weave:///…/call/<id>, …]` and `role: aero`; reverse link `c.feedback "pattern" → pattern-0042`
5. `wiki/index.md` row + `wiki/standings.tsv` row (round, role, score)
6. `debriefs/round_n.py` cell `credit` (defines `blame`) → cell `upgrade_pick` → cell `upgrade_aero` (defines `next_round_config`); `ctx.graph.ancestors("next_round_config")` lists 1–5's cells
7. `wiki/skill-impact.md` row: proposal id, role, unified diff, pattern ids cited, TEAM CLAIMED, OFFICIAL, verdict
8. Registry version `wandb-registry-scrutineer/aero:v4` with metadata `{parent_version, round_id, proposal_hash, wiki_pages_cited, official, claimed, verdict}` — https://docs.wandb.ai/guides/registry/
9. Signed chain entry `chain/000123.json` (§5) whose `predecessor` is 000122 and whose `defs_hash` is the hash of `next_round_config`

The upgrade scene's caption is generated from hops 4, 7 and 8, so the broadcast can only say *why* if the chain exists.

| **Runaway-loop / stuck overseer** | RACE CONTROL: a separate process polls the Weave callgraph every 30 s and can red-flag a lap that exceeds step or token limits | SICA async overseer (https://arxiv.org/html/2504.15228); W&B's named multi-agent failure modes "cascading assumptions, runaway loops, higher token costs" (https://www.brighttalk.com/webcast/20648/672150) |
