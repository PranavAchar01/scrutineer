# Fact-check: "Power Unit Engineer" via W&B Serverless RL + LoRA serving

Checked 2026-09-03 against live docs and the ART `main` branch (last commit 2026-09-04T03:12:58Z per GitHub API).

## Verdict

**Partially refuted.** The core mechanism is real and buildable, but three specifics in the claim are wrong or imprecise and must be corrected before they go into §4/§7 code:

| Claim fragment | Status | Correction |
|---|---|---|
| `art.TrainableModel` + `ServerlessBackend().train(...)` | SUPPORTED | Call shape is `result = await backend.train(model, train_groups, learning_rate=1e-5)`. There is **no** `model.train(...)` on `TrainableModel` (only `train_sft`). |
| "via ART GRPO" | IMPRECISE | ART markets itself as GRPO, but `ServerlessBackend.train` accepts only `loss_fn: Literal["cispo","ppo"]`; default resolves to `"cispo"` (or `"ppo"` if `ppo=True`). Group-relative reward normalisation is still on by default (`normalize_advantages=True`). Say "ART (CISPO/PPO group-relative RL)" or just "ART RL". |
| Trains a LoRA on `OpenPipe/Qwen3-14B-Instruct` | SUPPORTED | Listed as a serverless model ("our recommended model for users new to RL") and as a LoRA-servable base with max LoRA rank 16. Note the current official 2048 Colab uses `Qwen/Qwen3.6-27B`. |
| Auto-saves checkpoints as W&B Artifacts per step | SUPPORTED | "the LoRA checkpoint generated by each step will automatically be saved in ... W&B Artifacts"; serverless "always saves a trainable checkpoint for the next inference step". |
| Servable at `https://api.inference.wandb.ai/v1` via `wandb-artifact:///{team}/{proj}/power-unit:vN` | **REFUTED on the `:vN` suffix** | ART's canonical checkpoint reference is `wandb-artifact:///{entity}/{project}/{name}:step{N}` (alias `stepN` is what ART attaches; `latest` also). The W&B LoRA doc example uses `:latest`. `:vN` is W&B's generic artifact version index; it is not shown anywhere for inference and `vN` is not guaranteed to equal step N. Use `model.get_inference_name(step=N)`. The OpenAI client also needs `project=f"{WB_TEAM}/{WB_PROJECT}"`. |
| Ghost `:vN` and new `:vN+1` servable on one endpoint | SUPPORTED (with `:stepN`) | The model string is per request and "W&B dynamically loads your weights"; ART ships a unit test whose docstring is "run inference on multiple model checkpoints simultaneously". |
| "ART also auto-logs per-step KL and entropy via `model.log`" | **REFUTED as worded** | `backend.train()` docstring: "This method does NOT automatically log trajectories or metrics. Call model.log() explicitly". The metrics come back in `ServerlessTrainResult.metrics` with canonical keys `loss/kl_div`, `loss/kl_policy_ref`, `loss/entropy`, `loss/grad_norm`, `loss/train`, `loss/learning_rate`, `train/reward`, ...; you must call `await model.log(train_groups, metrics=result.metrics, step=result.step, split="train")`. Whether `loss/kl_div` is populated when `kl_penalty_coef=0.0` (the default) is UNVERIFIED. |

## Corrected text for the design

- §3 / §4 'self-improve': "W&B Serverless RL via ART (`art.TrainableModel(name="power-unit", project=..., base_model="OpenPipe/Qwen3-14B-Instruct")`, `ServerlessBackend()`, `await model.register(backend)`, `result = await backend.train(model, groups, learning_rate=1e-5)`; loss `cispo` by default). Every step's LoRA is auto-saved as a W&B Artifact aliased `step{N}`/`latest`."
- §4 'promote': "New driver = one string: `model.get_inference_name(step=N)` → `wandb-artifact:///{team}/{proj}/power-unit:stepN`; ghost = `:step{N-1}`. Both are per-request `model` values on `https://api.inference.wandb.ai/v1` (client must pass `project="{team}/{proj}"`)."
- §4 'audit': "KL/entropy are returned in `result.metrics` (`loss/kl_div`, `loss/kl_policy_ref`, `loss/entropy`) and become W&B run history only after `await model.log(groups, metrics=result.metrics, step=result.step, split="train")`. Set `kl_penalty_coef>0` if a non-trivial KL-to-reference number is wanted (behaviour at 0.0 UNVERIFIED)."
- §10 risk: training is free in public preview (no documented time cap); inference free tier is $100/month with per-project/per-user concurrency 429s; the official 2048 run takes ~2 h; LoRA rank ≤16.
- Appendix (15): base model is LoRA-servable — confirmed, rank ≤16.

## UNVERIFIED

- Whether `:vN` resolves on the inference endpoint (W&B artifacts do carry `vN` versions, but no doc or code shows it for inference); do not rely on it.
- Whether `loss/kl_div` is emitted when `kl_penalty_coef=0.0`.
- Exact `inference_base_url` ART sets after `register()` on the serverless backend (it returns the ServerlessBackend client's base URL; not confirmed to be literally `api.inference.wandb.ai`). The W&B docs endpoint works independently.

## Second independent pass (2026-09-03, later the same day) — additions only

Re-fetched every source above independently; the verdict table stands. New facts that the first pass did not carry:

1. **`run_name` is a required constructor argument on `TrainableModel` in ART `main`, and the artifact/inference name is built from it, not from `name`.** Source: https://raw.githubusercontent.com/OpenPipe/ART/main/src/art/model.py (fetched 2026-09-03), verbatim:
   ```python
   class TrainableModel(Model[ModelConfig, StateType], Generic[ModelConfig, StateType]):
       base_model: str
       # Durable checkpoint/W&B lineage; `name` remains the inference-serving alias.
       run_name: str
       ...
       def _storage_name(self) -> str:
           return self.run_name

       def __init__(self, *, name: str, run_name: str, project: str, entity: str | None = None, ..., base_model: str, ...)
   ```
   and in `serverless/backend.py`: `artifact_name = f"{model.entity}/{model.project}/{model._storage_name()}:step{step}"`. So the string the design should write is `wandb-artifact:///{team}/{proj}/{run_name}:stepN`. The ART docs example (`art.TrainableModel(name="agent-001", project=..., base_model=...)` at https://art.openpipe.ai/fundamentals/art-client) omits `run_name`; docs lag `main`. Version context from the GitHub API and PyPI (fetched 2026-09-03): GitHub tags v0.5.19 (2026-08-14), v0.5.17 (2026-03-13); PyPI latest `openpipe-art` is **0.5.18 (2026-05-23)** — pin the version you test against and check whether `run_name` is required there.

2. **W&B's own serverless-training model list** (https://docs.wandb.ai/serverless-training/available-models, fetched 2026-09-03, no page date): `meta-llama/Llama-3.1-8B-Instruct`, `OpenPipe/Qwen3-14B-Instruct` ("optimized by OpenPipe for building agents with finetuning"), `Qwen/Qwen3.6-27B`, `Qwen/Qwen3-30B-A3B-Instruct-2507`; other models "contact support@wandb.ai". Confirms the base-model half of the claim from the W&B side, not only from ART.

3. **Serverless Training limits page** (https://docs.wandb.ai/serverless-training/usage-limits, fetched 2026-09-03): "Training is free during the public preview period."; "Pricing for Serverless Training inference requests matches Serverless Inference pricing."; "Serverless Training supports up to 2,000 concurrent requests per user and 6,000 per project."; "Every plan includes at least 5 GB of free storage, which is enough for roughly 30 LoRAs." Higher limits: "request one at support@wandb.com". **No job-duration or step cap is documented** — the §10 "quota/time" risk should be restated as: concurrency 429s, the $100/month Free inference cap, and storage (~30 LoRAs at 80-150 MB each); not a training-time limit.

4. **The service does not document KL/entropy at all.** The API reference for `GET /v1/preview/training-jobs/{id}/events` (https://docs.wandb.ai/serverless-training/api-reference/training-jobs/get-training-job-events, fetched 2026-09-03) enumerates `gradient_step` as an event type but types its `data` as `object` with `additionalProperties: true` — no metric field names. ART's `_UPSTREAM_TRAIN_METRIC_KEYS` (`"entropy": "loss/entropy"`, `"kl_div": "loss/kl_div"`, `"kl_policy_ref": "loss/kl_policy_ref"`) is a *client-side rename table*; whatever keys the service actually emits pass through `_canonicalize_upstream_metric_key`, which returns unknown keys unchanged. So "KL and entropy are logged" is an inference from ART's code, not a documented service guarantee. Additionally, ART v0.5.17 (2026-03-13, https://github.com/OpenPipe/ART/releases/tag/v0.5.17) says "Remove beta KL divergence from training loss (#607)", and `kl_penalty_coef` defaults to `0.0` in both `TrainConfig` (https://raw.githubusercontent.com/OpenPipe/ART/main/src/art/types.py) and `ServerlessBackend.train`. Treat `loss/kl_div` as **present only if you set `kl_penalty_coef > 0`** (still UNVERIFIED at 0.0); `loss/entropy` is the safer audit metric, and the §4 'audit' row should say the values are *returned by `backend.train()` and logged by our explicit `model.log(...)` call*.

5. **Create-RL-job request schema** (https://docs.wandb.ai/serverless-training/api-reference/training-jobs/create-rl-training-job, fetched 2026-09-03): required `model_id` (UUID) and `trajectory_groups`; optional `experimental_config` with `learning_rate`, `loss_fn` ∈ {`cispo`, `ppo`}, `kl_penalty_coef`, `kl_penalty_source` ∈ {`current_learner`, `sample`}, `importance_sampling_level` ∈ {`token`, `sequence`, `average`, `geometric_average`}. No `grpo` option exists at the API level — reinforces the "via ART GRPO" imprecision.

6. **"Introducing Serverless RL" (2025-10-08, https://wandb.ai/wandb_fc/product-announcements-fc/reports/Introducing-Serverless-RL--VmlldzoxNDY0MDIzOQ)**: "Serverless RL hot-swaps your trained LoRA on W&B Inference between training steps"; "Serverless RL automatically logs metrics and traces at every training step to Weights & Biases". Note this is a 2025 marketing report; "automatically logs" there refers to the managed pipeline, whereas in current ART the client must call `model.log` (see table row 7).

Net effect on the structured verdict: unchanged — **partially refuted**. Mandatory corrections: (a) `backend.train(model, groups, ...)`, not `model.train`; (b) `:stepN` (or `model.get_inference_name(step=N)`), not `:vN`; (c) artifact name is `run_name`; (d) KL/entropy come back in `result.metrics` and are logged only by an explicit `model.log(...)`; `loss/kl_div` likely requires `kl_penalty_coef > 0`; (e) say "ART (CISPO/PPO, group-relative)" not "GRPO"; (f) quota risk = concurrency/inference cap/storage, not a documented training-time limit.
