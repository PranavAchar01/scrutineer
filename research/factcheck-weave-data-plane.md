## Corrections to carry into the design

1. **§5 link 1 / §10 "two-plane uncertainty" / Appendix (5)**: Replace "attribute propagation into nested ops is UNVERIFIED" with: verified for the classic op plane (`op.py::_create_call` reads the `call_attributes` ContextVar; docs: applies to "all traced operations within the context manager block"). It does **not** cross into conversation-SDK spans — stamp agent spans with `start_conversation(attributes={...})` (propagates to every turn/LLM/tool/subagent span) or `span.set_attributes({...})` while recording. Use a shared key set (e.g. `generation`, `role`, `lineage`) on both planes.
2. **§5 link 2 / §10 "Feedback payload cap 1 KB" / R3 F13**: Docs wording is "less than 1 KB when serialized" (strict `<`, not `≤`); notes capped at 1024 chars. The server on master enforces `CLICKHOUSE_MAX_FEEDBACK_PAYLOAD_SIZE = 1 MiB`. Keep 1 KB as the design budget (it is what W&B documents), but the real failure boundary is 1 MiB — put large scrutineer verdicts in a published object and reference its ref from the feedback payload.
3. **§5 link 6/7 / Appendix (6)**: Agent-span feedback API is `client.get_agent_span_feedback(span_id)`, `get_agent_turn_feedback(trace_id)`, `get_agent_conversation_feedback(conversation_id)` (weave ≥ 0.53.2, released 2026-07-16). It is undocumented on docs.wandb.ai today; pin `weave>=0.53.2` and smoke-test at kickoff.
4. **§2 'document' / Appendix (8)**: `weave.set_view` requires an active call (raises via `require_current_call()`); `EvaluationLogger.set_view(...)` attaches a view to the evaluation's `evaluate` call summary and is the right hook for per-generation reports outside any user op.
5. **Appendix (13)**: `weave.publish` also takes `aliases=[...]`, so champion promotion can be a single `weave.publish(obj, name=..., tags=[...], aliases=["champion"])` or a later `client.set_aliases(ref, "champion")`.
