# LOOP.md — SCRUTINEER: "THE OPTIMIZER" (definitive loop design)

Design frozen 2026-09-03 for CoreWeave Hacks "The Loop" (Sat 13 Sep 11:15 hacking begins → Sun 14 Sep 13:00 submissions ≈ 26 h; https://luma.com/coreweavehacks). Winner of the three-design tally was DESIGN-A ("The Optimizer"); this document keeps A's identity and mechanism — block-coordinate descent over a team graph with counterfactual-replay credit and a `selection:gen-n` object that alone can start an upgrade — and grafts in the specific elements the judges asked for from B (document as the hand-off contract, provenance chain, wiki asymmetry, manifest verification) and C (TypeSafe pit-wall strategist, simulator/curriculum role, gain-per-dollar selection, per-role W&B runs, RL started at T+4h with KL/entropy eligibility). ## 1. Name and one-sentence pitch

**SCRUTINEER — THE OPTIMIZER.**

*A Formula 1 constructor where every engineer on the pit wall is an agent with its own part number; after every race the stewards prove which engineer cost the lap by replaying the race without them, only that engineer gets upgraded, the upgrade is homologated in a debrief that must reproduce the evidence, and every promotion carries a signed receipt — or a black flag.*

The sentence a judge should say afterwards: *"It told me which engineer cost the lap, proved it by replaying without them, refused to upgrade anyone when the evidence was thin, upgraded only that engineer when it wasn't, and showed me the one time it caught itself cheating."*

Positioning line in the organisers' own words (R9 F1, F8, F15): a colony of agents keeping each other honest, that learns from its own scars — production signals become benchmarks, quality gates decide what gets promoted, and every upgrade has receipts.

## 2. The loop

**Technical thesis (REGS panel only).** The team is a directed graph G of role-nodes; node r owns exactly one upgradeable artifact θ_r (an Agent Skills directory, a harness module, a typed threshold table, a versioned dataset, or a LoRA). One generation is one block-coordinate-descent step on θ = (θ_r)_r that minimises expected lap time on a sealed circuit the optimizer never sees, under a fixed cost cap. What makes it an optimizer rather than "mine traces → patch prompt" (the WeaveHacks-3 table stakes: KayOne, OpenClaw Trace, soft beds — R8 F7) is that each generation (a) computes per-role credit by counterfactual replay on Weave traces (SHARP/C3/REFLECT family, the only mechanism with near-ground-truth status per R1: https://arxiv.org/abs/2603.06859, https://arxiv.org/abs/2606.09071), (b) accumulates it statistically before acting (Who&When: "statistical-level attribution works better than instance-level", https://arxiv.org/abs/2505.00212), (c) mutates only the blamed node, chosen by gain-per-dollar inside a CI-gated candidate set (Optimas/GEPA/LLMSelector update one component at a time: https://arxiv.org/abs/2507.03041, https://arxiv.org/abs/2507.19457, https://arxiv.org/abs/2502.14815), (d) refuses to upgrade anyone when no node qualifies and runs a matched-budget test-time-scaling ghost instead (https://arxiv.org/abs/2607.12227), and (e) promotes only through a chain of gates the mutating agent cannot write, with the debrief document itself as one of those gates.

## 3. The cast

Ten technical roles plus one human: five on the CAR (in-lap), four on the PIT WALL (round-level), one in the garage (PIT CREW, a script). Kept small because self-organising teams lose up to 41.1 % against their best member as size grows (https://arxiv.org/abs/2602.01011) and auto-generated MAS "consistently underperform CoT-SC" (https://arxiv.org/abs/2606.13003). Every role's artifact validates as an Agent Skills directory where applicable (`skills-ref validate`, https://agentskills.io/specification); `metadata.version` is the part number on the garage card.

**Inner CAR pipeline per lap (one task item):** for each driver step: `STRATEGIST.call → (engine_mode → TYRES profile) → AERO.shape_context → POWER_UNIT.drive → DATA.run_tools (tests in Sandbox)`, until STRATEGIST returns `BOX` (submit) or `RETIRE`, or the step cap (12 steps per lap, set in `REGS.md`) is hit. The driver model is `OpenPipe/Qwen3-14B-Instruct` (LoRA-servable, tool-calling, $0.05/$0.22 per 1M; R4 F13/F8) so that `power-unit:step{N}` actually races.

**Upgrade rarity ladder with part-number prefixes** (Weng's ladder, https://lilianweng.github.io/posts/2026-07-04-harness/; Motorsport Manager tiers, R8 F24): `P-` prompt patch < `R-` references/context < `S-` search policy / thresholds < `H-` harness code / tool schema < `W-` weights; `C-` = circuit (curriculum). The audience can tell a wing tweak (`AERO R-v4`) from a new engine (`POWER UNIT W-v2`).

## 4. Sponsor × stage matrix

## 5. Credit assignment — from a Weave trace to "upgrade the aerodynamicist"

**Objective per lap** (SICA utility, https://arxiv.org/html/2504.15228, mapped to seconds):

```
U      = 0.5·pass + 0.25·(1 − min(1, cost_usd/cap_usd)) + 0.25·(1 − min(1, wall_s/300))
lap_s  = 60 + 40·(1 − U)            # 60.0 s perfect, 100.0 s worst; timeout ×(1−τ), τ = 0.5 on U
quali_s = mean over QUALI (TEAM CLAIMED)     race_s = mean over SEALED (OFFICIAL)
```

`pass` is execution feedback (hidden tests in a sandbox) — rung 2 of the verification hierarchy; never an LLM judge for the official score (https://arxiv.org/html/2607.07663 §5.2).

**The chain, link by link (each link is an addressable object, each has a source):**

1. **Span.** Every role call is a classic `@weave.op` with `attributes={"role": "aero", "generation": 7, "lap": 14, "theta_hash": "…"}`, full `inputs`/`output`, `trace_id` grouping the lap, `parent_id` building the tree (https://docs.wandb.ai/weave/guides/tracking/call-schema-reference). The lap also has a conversation for the Agents view; credit lives on the classic Calls because feedback and scorers are documented there (R3 §3.2; feedback on agent spans landed in v0.53.2 but attribute propagation into nested ops is UNVERIFIED — close at kickoff).
2. **Lap outcome.** `LapTimeScorer` result stored as feedback on the lap's root call by `call.apply_scorer` ("Weave automatically stores scorer results", https://docs.wandb.ai/weave/guides/evaluation/scorers). Failing lap := `U < U_ghost − 0.05` on the same item.
3. **Signal.** Role-named custom Signals (`aero-context-miss`, `strategist-derail`, `tool-schema-error`, `tyre-misread`) tag turns as they land, scoped by agent (https://docs.wandb.ai/weave/guides/tracking/create-custom-signal). Created by hand in the UI before H12, or from Python via `weave.ClassifierMonitor(...).activate()` (https://docs.wandb.ai/weave/reference/python-sdk; rendering on the Agents › Signals tab smoke-tested first). Cheap first hint; never trusted alone.
4. **Typed triage — CREDIT ROUTER.** For every failing lap, one typed call: input = the lap's call tree (inputs and outputs of every role, tool exceptions, Signal tags, MAST mode list); output = `{blamed_role: enum[AERO, STRATEGIST, POWER_UNIT, TYRES, DATA], mast_mode: enum[14], blame_share: dict, confidence: float, needs_ablation: bool}` (MAST κ = 0.77 annotator precedent, https://arxiv.org/abs/2503.13657; Who&When all-at-once prompt, https://arxiv.org/abs/2505.00212). Backend A System1 (described by the vendor as producing calibrated decisions; no public API doc or response shape exists — UNVERIFIED until the H0 capture — so its calibration is measured on-site exactly like the fallback's); Backend B `gpt-oss-20b` strict `json_schema` at $0.03/$0.13 per 1M (https://wandb.ai/site/pricing/inference) with a 3-sample vote as pseudo-confidence, labelled UNCALIBRATED in REGS. Written as `call.feedback.add("router", payload)` on the lap root. Expected agent-level accuracy 55–70 % (Who&When 54 %, AgenTracer 70 %, https://arxiv.org/abs/2509.03312) — the router proposes, the next link verifies.
5. **Counterfactual confirmation — PARC FERMÉ REPLAY.** For the top-2 roles by `blame_share` (always if `needs_ablation` or `confidence < 0.7`; top-1 otherwise), fix the history up to r's call (C3 "fixed interaction history") and re-run r plus the downstream pipeline on r's recorded `inputs`, temperature 0, 2 seeds, in a sandbox, as Weave calls with `attributes={"replay_of": call_id, "masked_role": r, "mode": …}`. Three modes, chosen by the state of θ_r:
   - **Ghost-swap** (θ_r changed since gen n−1): re-run r with the ghost car's θ_r. `credit_r = lap_s(actual) − mean(lap_s(ghost r))` (SHARP `credit = R(τ) − R(τ \ m)`, https://arxiv.org/html/2602.08335v2). Detects regressions of the last-upgraded role.
   - **Patch-replay** (θ_r unchanged since the ghost — ghost-swap is identically zero, the gap the judges named): the `BlameScorer` (a different model family) emits a diagnosis-specific corrected output for r's step; replay downstream; the verdict stands only if the lap flips (REFLECT, https://arxiv.org/abs/2606.09071; TraceElephant "dynamic agentic" 67 %/33 %, https://arxiv.org/abs/2604.22708). `credit_r = lap_s(actual) − lap_s(patched)`.
   - **Null-stub** (always, cheap): r replaced by a null/identity stub. Distinguishes "r is worse than it could be" from "r is load-bearing".
   Per-role patch definition (what a "corrected output" means): AERO — replay with the missing reference inserted into the assembled context; STRATEGIST — replay with the ghost threshold table (`BOX`/`RETIRE` re-decided); TYRES — replay with `engine_mode + 1` (more samples, lower temperature); DATA — replay with the schema-repaired tool call; POWER_UNIT — **excluded** from patch-replay (a "corrected" driver output is the solution itself, which would conflate "better driver" with "someone solved it"); it is credited only through ghost-swap and the `agent_error` rule.
   Cost ≤ 2 roles × 2 seeds × ≈10 failing laps ≈ 40 partial downstream runs per generation; on the 14B driver at $0.05/$0.22 per 1M that is cents.
6. **Ledger row.** `call.feedback.add("scrutineer.credit", {"role": r, "delta_s": credit_r, "ci": [lo, hi], "mode": "patch", "seeds": 2, "replay_ref": "<weave object ref>"})` on the original role call — kept under the documented 1 KB feedback cap (R3 F13) by publishing the full replay record (ids, prompts, outputs) as a Weave object and referencing it. Append-only, on FIA TELEMETRY, never in a file the improver can edit.
7. **Standings (statistical blame).** `client.get_calls(filter=CallsFilter(...), include_feedback=True).to_pandas()` → per role over the generation: `n_r` confirmed incidents (`credit_r > 0.5 s`), `blame_r = Σ credit_r`, bootstrap 90 % CI over incidents (Causal Agent Replay reports CIs, https://arxiv.org/abs/2606.08275), `var_r`. Published as `standings:gen-n` (Weave object) and as one W&B run per role (`round-{n}-{role}`) so the ARIA board plots exactly what the ledger saw. The debrief's `credit` cell draws blame bars **with CI whiskers** and the router's fault-injection confusion matrix beside them.
8. **Selection rule (the optimizer step), written as `selection:gen-n`:**

```
eligible = { r : n_r ≥ 5 and CI90_lo(blame_r) > 0 }                     # never on one lap (Who&When)
if generalisation_gap > 0.25 or zero_variance_groups ≥ 0.40:            # pit-wall CIRCUIT branch
    r* = SIMULATOR; path = circuit; rule_fired = "circuit"               # its own generation: no harness
                                                                         # mutation; ghost re-timed on vN+1
elif agent_error on ≥ 60 % of confirmed incidents and no harness role flips ≥ 60 %:
    r* = POWER_UNIT; path = weights                                      # Co-Harness abstention label
elif override_pick in next_round_config[n-1]:
    r* = override_pick; rule_fired = "principal_override"
elif eligible == ∅:
    r* = None; rule_fired = "no_upgrade"                                 # run the matched-budget TTS ghost (k+1)
else:
    r* = argmax_{r ∈ eligible}  blame_r · p_fix(r) / (cost_r + λ·hours_r) # gain per dollar, λ = $0.50/h
    ties → highest var_r                                                 # JoyAgents-R1 "maximal reward fluctuations"
Phase B (every third accepted generation; pit-wall service roles, first eligible in this order wins;
    each has a cost_r/hours_r row so expected_gain_per_usd is computable for all ten nodes):
    RACE_ENGINEER  if fix_precision < 0.4 or regression_precision < 0.2 over its last 3 manifests
    ROUTER schema  if router_precision < 0.5 over 3 rounds               # SCRUTINEER's θ; Principal sign-off
    HISTORIAN      if marimo-check first-pass rate < 0.6 over 3 rounds or page utility < 0.3
    PIT_CREW       if local-pass / sandbox-fail rate > 0.2 over 3 rounds
```

   `p_fix(r)` = fraction of r's past upgrades that moved OFFICIAL; a **labelled prior of 0.5** until ≥ 3 outcomes exist for r (the debrief prints "prior" next to it). Per-role cost table (from `REGS.md`; numbers from R4 F8/F10, https://wandb.ai/site/pricing/inference, and GEPA metric-call counts) — one row per node so `expected_gain_per_usd` is computable for all ten: AERO / DATA harness patch via RACE ENGINEER ≈ $0.30 / 15 min; TYRES `tyres.yaml` refit ≈ $0.05 / 5 min; STRATEGIST refit ≈ $0.03 / 2 min; POWER UNIT RL ≈ $0.50–1.50 / 2 h (16 items × 6 rollouts × 15 steps on the 14B driver, training free in public preview); SIMULATOR circuit ≈ $0.20 / 10 min plus one ghost re-timing on the new circuit ≈ $0.15; RACE ENGINEER `SKILL.md` patch (Phase B) ≈ $0.40 / 20 min; SCRUTINEER router-schema change ≈ $0.10 / 10 min + Principal sign-off; HISTORIAN template/skill patch ≈ $0.20 / 15 min; PIT CREW `install.sh`/image patch ≈ $0.05 / 10 min. Upgrade cost is charged to the role's `cost_r`, shown on the DESIGN OFFICE ORDER card, and sits **outside** the $3 race + replay cap (§6). Sign convention everywhere (`predicted_delta_s`, `credit_r`, `Δquali`, `Δsealed`): **seconds gained, positive = faster**, printed as GAIN on screen. The object carries `{r*, path, blame_r*, ci, n_r*, p_fix, cost_r, hours_r, expected_gain_per_usd, rule_fired, alternatives: [...]}` — so the REGS panel can show why a cheap threshold refit beat a weight update. **This object is the only thing that can start the upgrade scene.**
9. **Hand-off.** The RACE ENGINEER's headless prompt receives `selection:gen-n`, `wiki/index.md`, the pattern pages with `role == r*`, `skill-impact.md`, and `hypotheses/round_n.md` (in UNATTENDED MODE a one-line file, `provenance: none (unattended)`) — nothing else (GEPA `component_selector` returning `[r*]` in the library path, https://github.com/gepa-ai/gepa). It may only touch `skills/{r*}/` or `harness/{r*}.py` (scope gate). For non-harness picks the controller dispatches instead: RL job (POWER UNIT), refit script (STRATEGIST), SIMULATOR session (circuit). A circuit pick ends the generation once the ghost has been re-timed on `practice-circuit:vN+1` (Δquali vs ghost is only meaningful on one dataset); the next harness mutation starts at gen n+1.
10. **Verification of the improver's own forecasts — `manifest_check` at gen n+1.** The evaluator (holder of the per-item vectors) checks `predicted_fixes` and `at_risk_regressions` against QUALI per-item pass vectors and `predicted_delta_s` against measured Δsealed; writes `fix_precision`, `regression_precision`, `delta_error` into the RACE ENGINEER's standings and into `wiki/skill-impact.md`. This is the evidence Phase B lacked in DESIGN-A.
11. **Meta-credit for the router.** `router_precision = P(OFFICIAL improved | router blamed r and r was upgraded)`; below 0.5 over three rounds the SCRUTINEER's next target is the router schema (add a MAST mode, raise the ablation threshold) — the "colony keeping each other honest" archetype.
12. **STRATEGIST refit (exact, so the debrief can reproduce it).** Input: the last generation's decision ledger (every `PitWallCall` with `p_finish_under_cap`, `confidence`, `engine_mode`, step index) joined to lap outcomes (`U`, cost, wall). Objective: choose `box_when ∈ {0.25, 0.30, …, 0.50}`, `retire_when ∈ {0.05, 0.10, 0.15}` and the engine-mode ladder (five monotone `p_finish` cut-points) that maximise mean U on QUALI under replayed decisions, subject to cost-overrun rate ≤ 5 %; ties → fewer late-`BOX` incidents. Output: `strategist/thresholds.yaml` + `{objective, overrun_rate, n_decisions}` written into the debrief's `strategist` cell and into `selection:gen-n.alternatives`. Deterministic, ~2 min, no model call.

**Calibrating the router (two hours, real).** Take 10 passing laps × 5 CAR roles; corrupt one role's output programmatically (AERO: drop the retrieved reference; STRATEGIST: force `RETIRE` at step 1; POWER UNIT: swap the solution for a wrong-but-plausible one from `gpt-oss-20b`; TYRES: T = 1.5, k = 1; DATA: break a tool schema) — AgenTracer's fault-injection recipe (https://arxiv.org/abs/2509.03312). Measure router recall per role for both backends; the confusion matrix is a cell in every debrief and is the credibility number for the credit cell.

**Worked example — "upgrade the aerodynamicist".** Lap 14, gen 7: hidden tests fail. Router: `{AERO 0.61, POWER_UNIT 0.27, conf 0.58, needs_ablation: true}`. AERO's θ is unchanged since gen 6 → patch-replay: BlameScorer supplies the missing reference in AERO's output; downstream re-run passes twice → `credit_AERO = +12.8 s`. Null-stub replay fails → AERO is load-bearing, just wrong. Nine such incidents this generation: `blame_AERO = +38 s`, CI90 [21, 55], n = 9 ≥ 5 → eligible. `expected_gain_per_usd = 38 × 0.5 / (0.30 + 0.5·0.25) = 44.7 s/$` vs STRATEGIST `21 × 0.5 / (0.03 + 0.5·0.03) = 233 s/$` — STRATEGIST has n = 4 and is ineligible, so `selection:gen-7 = {r*: AERO, rule_fired: "gain_per_usd", …}`. HISTORIAN's `pattern-0042` (role: aero, evidence: 9 call refs, `call.feedback.add("pattern", {"id": "pattern-0042"})` on each). RACE ENGINEER reads `selection:gen-7` + `pattern-0042`, emits `AERO R-v4` diffs A/B to `skills/aero/references/retrieval.md` + manifest. Pit crew installs; A wins QUALI; SEALED: Δquali +0.9 s, Δsealed +0.7 s, smoke +0.4 s (all same sign), no per-item regression, cost $2.41/$3.00; verdict LEGAL 0.93; debrief reproduces all of it, `gate_ok = True`; APPROVE; `wandb-registry-scrutineer/aero:v4` alias `champion`; chain row signed; scene caption is generated from `selection:gen-7 → pattern-0042 → diff hash → aero:v4` and cannot be written without that chain.

## 9. Prize-by-prize argument

**Best Loop Design.** All five verbs plus audit and promote have a named mechanism and a named artifact (§2). Credit is proposed by a typed router and verified by counterfactual replay in three modes, accumulated with bootstrap CIs, and turned into a single `selection:gen-n` object that alone can start an upgrade; the selection is gain-per-dollar inside a CI-gated set. The loop refuses in two ways — BLACK FLAG and `no_upgrade` — and the improver is scored on its own forecasts (`manifest_check`) and can itself be upgraded (Phase B), as can the router (meta-credit). The debrief is a gate, not a tail. This is the "colony keeping each other honest" archetype with receipts (R9 F1/F8/F15), and none of the WeaveHacks-3 trace-mining projects had per-role attribution, an auditor that can reject, a public/private split, or an upgrade scene (R8 F7).

**Most Production-Ready.** Evaluator, sealed data, lineage and scrutineer live outside the improver's write set by permissions (separate team, service-account key, OS users), not by instruction — the exact failure DGM demonstrated (https://sakana.ai/dgm/). Every promotion is an Ed25519-signed, hash-chained record with parent links that a 40-line verifier replays; `results.tsv` and the Registry mirror it. The pit wall runs hundreds of typed decisions per race (thousands per generation) at cents with `RETIRE` enforcing the budget in-lap; OFFICIAL crosses from the sealed team to the public project only as the evaluator's aggregate `official:gen-n` object (score + opaque per-item booleans), so no LLM agent ever reads a sealed item; overnight the loop runs in a declared UNATTENDED MODE whose auto-approve rule is itself logged in every chain row; a 30 s overseer catches stuck laps; cascading assumptions are prevented by roles consuming each other only through telemetry. The minimal real path is a ten-hour build with labelled fallbacks for every rail.

**Best Use of Weave.** Both data planes used for what each does: classic ops + `weave.attributes` for feedback/scorers/`Dataset.from_calls`, the conversation SDK for the Agents view with one agent per role and `agent_version` = part number; role-named Signals as the first attribution hint; `Evaluation` (trials) + `EvaluationLogger` linked to spans; the ledger as feedback rows queried with `get_calls(include_feedback=True)`; `standings`/`selection` as published objects; `set_aliases` from a single key; Leaderboard; `set_view` from inside the Historian's op; bidirectional `pattern` feedback. The Race Engineer's own Claude Code session is traced by the Weave plugin, so the improver is observed by the same telemetry it improves against — Turlay's "quality flywheel" (production signal → offline dataset via `Dataset.from_calls` → `practice-circuit:vN`) is literal.

**Best Use of ARIA.** ARIA has a real, non-decorative job with provenance: it reads one W&B run per role per round (the same numbers the ledger used), builds the TRAINING BOARD, drafts the season Report, and its round-n+1 hypothesis — with the Report URL as its provenance line — is a required input to the Race Engineer. Its recommendation is compared with the ledger's pick and logged as `aria_agrees`. ARIA can also run experiments through a W&B Launch queue with an active agent ("ARIA can recommend and run new experiments", https://docs.wandb.ai/aria/autoresearch; "Run experiments and sweeps to test new ideas", https://docs.wandb.ai/aria/overview, both fetched 2026-09-03); we wire no Launch queue in 26 h, so ARIA is recommend-only here **by our scoping choice, not by product limit**, and the Team Principal's APPROVE is our gate (the "researchers stay in control by approving launches" line is marketing copy at https://wandb.ai/site/agent/, not a documented ARIA approval feature — Julia Rose's lens, R9 F14). REGS says exactly that.

**Best Use of marimo.** We found no published marimo notebook over Weave traces (searched 2026-09-03: marimo gallery, weave-mods, W&B docs — R5 F19); if one exists, ours is the first to be a promotion gate. The debrief is executable and causal: `app.run(defs=…)` is the hand-off contract to the next round, the `upgrade_pick` dropdown recomputes `next_round_config` live (GHOST UPGRADE), `marimo check --strict` plus a script-mode run (explicit `raise`) are the homologation gate, and promotion cannot happen without `gate_ok`. The archive is served with `with_dynamic_directory`, each round has a molab link, and the marimo-pair skill driving a live `marimo edit` kernel is the stage flourish (code mode is an internal, agent-only API — flourish, never gate). Understanding, auditability, reactivity — the three words marimo's own rubric uses (R5 F20).

**Best Use of TypeSafe AI.** The pit wall is a typed-decision endpoint used where chat models are the wrong tool: unattended, high-frequency, schema-bound decisions whose confidence is **measured, not assumed** — the STRATEGIST (hundreds of `PitWallCall`s per race, thousands per generation, `RETIRE` under the cap, an upgrade that is a table refit of thresholds, not a prompt), the CREDIT ROUTER (`needs_ablation` at low confidence routes to a real replay — "know when uncertain"), and the SCRUTINEER (`REFER_TO_STEWARDS` at low confidence; unpersuadable by prose). The on-stage claim is not "System1 is calibrated" — no public API doc supports that; the only TypeSafe sources are https://typesafe.ai/, the ToS, one talk and newsletter posts (R6) — but "here is how calibrated the pit wall was": the reliability diagram and Brier score are computed for whichever backend ran (System1 if a key and its response shape are captured at H0; otherwise the fallback chat model constrained to the schema and labelled UNCALIBRATED) and the backend is named beside the curve. Volume and cost per decision (≈ 24× cheaper than `Qwen/Qwen3.6-27B` on the same endpoint at 300 in / 60 out tokens on the fallback, from https://wandb.ai/site/pricing/inference; measured on-site for System1) are on screen; the ToS is respected (decisions, never distillation targets, https://typesafe.ai/terms) and said so in REGS. Diogo's thesis — "do not use AI for decisions with stakes to your business" unless it is calibrated (R6 F6) — is the pit wall, with the calibration number shown rather than claimed.
